Apache Flink چیست؟

یک چارچوب توزیع‌شده و موتور پردازش برای محاسبات حالت‌دار روی جریان‌های داده — چه نامحدود (unbounded)، چه محدود (bounded).

مسئله‌ای که حل می‌کند

  • داده پیوسته می‌رسد و پایان ندارد
  • رویدادها دیر یا بدون ترتیب می‌رسند
  • محاسبه به «حافظه» (state) نیاز دارد
  • ماشین‌ها از کار می‌افتند، نتیجه باید درست بماند

Batch در برابر Stream

Batch

  • داده انباشته می‌شود
  • پردازش پس از آماده‌شدن دسته آغاز می‌شود
  • نتیجه یک‌جا و با تأخیر ظاهر می‌شود

Stream

  • رویدادها پیوسته می‌رسند
  • پردازش تدریجی و رویداد‌به‌رویداد
  • نتیجه مدام به‌روز می‌شود
تصویرسازی مفهومی با نرخ ورودی یکسان؛ اعداد، زمان‌بندی واقعی نیستند.
۰۵ · معماری

معماری Apache Flink

  1. Client برنامه را به JobGraph تبدیل و ارسال می‌کند
  2. Dispatcher یک JobMaster برای job می‌سازد
  3. JobMaster از ResourceManager slot می‌خواهد
  4. ResourceManager از TaskManagerها می‌خواهد slotها را به JobMaster عرضه کنند
  5. JobMaster وظایف (tasks) را در slotها مستقر (deploy) می‌کند
  6. TaskManagerها داده را مستقیم مبادله و heartbeat می‌فرستند
اجرا روی Standalone، Kubernetes یا YARN امکان‌پذیر است.
۰۶ · مدل اجرا

Source → Transformation → Sink

DataStream API (simplified)
env.fromSource(kafkaSource, watermarkStrategy, "orders")
   .map(parse)                  // transformation
   .filter(e -> e.amount > 0)
   .keyBy(e -> e.userId)         // repartition by key
   .window(TumblingEventTimeWindows.of(Duration.ofMinutes(1)))
   .sum("amount")
   .sinkTo(sink);

۰۷ · دموی B

Distributed Computing با Parallelism

Parallelism

هر عملگر به چند subtask موازی تقسیم می‌شود؛ هر کلید همیشه به یک subtask می‌رود.

JobManager

هماهنگ‌کنندهٔ job: زمان‌بندی، checkpoint و بازیابی.

TaskManager

وظایف را در task slotها اجرا و داده را بین خود مبادله می‌کند.

در Flink واقعی، تغییر parallelism یک job در حال اجرا معمولاً با savepoint و راه‌اندازی مجدد (یا scheduler تطبیقی) انجام می‌شود.
۰۸ · حافظه

Stateful Processing چرا مهم است؟

State چیست؟

اطلاعاتی که عملگر از رویدادهای گذشته نگه می‌دارد: شمارنده، پنجره، نشست، الگوی در حال شکل‌گیری.

Keyed State

ValueState · ListState · MapState — بر اساس کلید پارتیشن می‌شود و محلی خوانده می‌شود.

State Backend

HashMapStateBackend (heap) یا EmbeddedRocksDBStateBackend (دیسک محلی) برای stateهای بزرگ.

۰۹ · معنای زمان

Event Time در برابر Processing Time

Event Time

زمانی که رویداد واقعاً رخ داده و درون خود رکورد است. نتیجه با پردازش مجدد یکسان می‌ماند.

Processing Time

ساعت ماشینی که رویداد را پردازش می‌کند. ساده و سریع، اما به تأخیر شبکه و بار سیستم حساس است.

۱۰ · پنجره‌ها

Windows و Watermarks

Tumbling Window

بازه‌های ثابت و بدون همپوشانی روی event time.

Watermark

ادعای پیشرفت event time: «رویداد جدیدی با زمان ≤ W انتظار نمی‌رود».

Late Events

پس از بسته‌شدن پنجره: allowedLateness یا side output.

Fault Tolerance با Checkpoint

  1. ۱اجرای عادی
  2. ۲ساخت checkpoint
  3. ۳خرابی عملگر
  4. ۴بازیابی از آخرین checkpoint

Barrierهای checkpoint در میان رکوردها جریان می‌یابند و یک snapshot سازگار از state و offset منبع می‌سازند (asynchronous barrier snapshotting). Exactly-once انتها‌به‌انتها به sink تراکنشی یا idempotent نیاز دارد.
